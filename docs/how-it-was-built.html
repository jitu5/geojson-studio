The whole journey

Seven steps, one plan file

The skill is a four-stage recipe for AI coding agents: Requirements, UX design, UI structure and Build. Each stage fills in one section of a single JSON plan, and normally ends at a gate where the user approves before the agent moves on. The agent added a research step at the start and a verify step at the end.

Step 0 · before the skill starts

Take the reference apart

"Like geojson.tools" is vague, so the agent made it precise. It read the reference site's page and its JavaScript bundle and wrote down every behaviour. The stage 1 doc asks for this: "Understand the brief thoroughly. Read the host/product if named — don't guess."

What was read
index.htmlindex.jsloadData.jshereMap.jscoordTools.jsheatMap.jspropertyLabels.jseventHandling.jscommon.jstile overlays
What it confirmed
  • The map is drawn with HERE XYZ Maps (@here/xyz-maps), as the brief suspected, and the editor is Monaco.
  • It's open source under MIT, by HERE.
  • Its HERE API key sits inside the public bundle. That key belongs to HERE, so it was never used.
  • Its heat map works by writing colours into your JSON.
Behaviour list carried over
  • Map and panel side by side, with a draggable divider and a map-only mode
  • JSON editor that redraws the map on every valid edit
  • Load by file picker, by dropping on the map or on the editor (which merges), or by URL with an optional Authorization header
  • Deep links: ?url=, #url=, several URLs split by ;, ?maponly, ?map=lng,lat,zoom
  • Per-feature validation, with an alert listing the features that failed
  • Click a feature: highlight it, show its properties, zoom to it, select its text in the editor
  • Click a property: highlight every feature with the same value
  • Coordinate tools (point, distance, bounding box), labels, heat map, tile grids
  • The view is remembered between visits
rule
The line drawn hereCarry over the behaviour and nothing else. The look, the code and the map stack would all be new, and the reference's branding would not be copied. That rule went into the plan as a constraint.
Stage 1 · requirements

One goal, and where the code lands

The skill wants this stage kept lean: one goal, the actors, a delivery contract, capability-level scope, and the constraints and assumptions. No screens and no stories yet. The stage can only close when openQuestions is empty.

data_objectdocs/plan/geojson-studio.ui-plan.json · requirements
// excerpt
"goal": "Let anyone drop, paste, or link GeoJSON and immediately see it on an interactive map, then inspect, edit, measure, and style the features — built with QBDS.",
"actors": [
  "analyst checking a geospatial export",

  "QBDS only: @qbds registry components, TOKENS.md utilities, Material Symbols Sharp icons, no raw hex in UI chrome …",
  "Must work with no API keys …",
  "Do not copy the reference product's branding, logo, or look"
],

"assumptions": [ /* 8 decisions, see the questions below */ ]

Why greenfield? The skill sorts every job into one of three delivery modes: greenfield (a new app in an empty folder), pages (new screens in an existing app) or feature (a change inside an existing screen). Nothing existed yet, so this is greenfield. That puts the shell, routing and QBDS setup in scope, and calls for the scaffold script.

Why the actors matter. Three kinds of user shaped later choices. The analyst wants to see data now, so the app has instant load and samples. The data engineer needs exact error locations, so it has the gutter markers and an error list. The consultant needs labels and colours for a client call.

Scope, 12 items: split layout, the loaders, live editor with validation, every geometry type with simplestyle, inspection and two-way sync, type filters, coordinate tools, labels and choropleth, tile grid, basemaps, theme and persistence, and tests.

Questions the agent would have asked hereanswered as decisions instead
helpThe reference draws its map with HERE XYZ Maps. Use the same SDK?
HERE XYZ MapsMapLibre GL JS

HERE's SDK shows no basemap without an API key, and the only key at hand was the one inside the reference's bundle, which belongs to HERE. MapLibre draws the same GeoJSON on free basemaps (CARTO, OpenFreeMap). HERE basemaps come back automatically if you add your own key.

helpMonaco, like the reference, or a lighter editor?
MonacoCodeMirror 6

A fraction of the size, and its theme reads QBDS CSS variables, so dark and light just work with no second theme to maintain.

helpVite or Next.js?
ViteNext.js

The skill's default. It's one screen with no routes and no server rendering, and it deploys as static files.

helpWhere should the code go?
New folder, isolated copyInside an existing app

The brief asked for a separate work tree. The folder went into delivery.targets, which is the skill's write contract: nothing outside it gets touched.

helpWhich reference features are in scope?
All but threeEverything

Left out: HERE Data Hub spaces (a retired HERE service), HERE-only association_ids highlighting, and the HERE tiling scheme. All three need HERE credentials. XYZ, quadkey and TMS grids replace the HERE scheme.

helpThe reference's heat map rewrites your JSON. Do the same?
Edit the JSONColour at render time

A viewer should never change your data behind your back. Colours are computed when the map is drawn, and the JSON stays as you wrote it.

helpFetch samples from the web, or ship them?
Remote linksBundled, generated

Works offline and never fails on a host that blocks cross-origin requests. Loading by URL still covers remote data.

helpWhat about very large files? And tests?
Editor read-only over 10 MBUnit + browser tests

The map still draws big files; only the editor steps aside. The brief said "test all of it", so tests went into scope as their own item.

Stage 2 · UX design

Six stories that complete the goal

The skill's model is one goal, split into several stories. Each story has the same three parts: the story (who wants what and why), the visual (what's on screen) and the interaction (what happens when you act). The skill prefers "fewer sharp stories over one mega-story".

space_dashboard
The UX context, decided firstThe map is the hero, about 62% of the width, and panels never cover it. The tool panel sits on the right, about 38%, with Editor, Data and Tools tabs. Density is compact, because this is a working tool, not a dashboard. Short-lived results go in toasts; lasting problems go in an inline alert. Map data is coloured like chart data.
upload_fileload
Load data

An analyst has a GeoJSON export and wants to see it now: drop files anywhere, browse, paste a URL, or pick a sample. Shared ?url= links load on open.

Visual
Data tab with Files, From URL and Samples; a full-window overlay while dragging.
Interaction
Several files merge into one collection; the map fits the data; a toast confirms.
edit_noteedit
Edit and validate

A data engineer fixes a broken export, watches the map update as they type, and is told exactly which features are wrong and why.

Visual
Action row, validation status, an alert listing failures, and an editor with lint markers.
Interaction
Redraw 300 ms after typing stops; invalid JSON keeps the last good map.
ads_clickinspect
Inspect features

Click a polygon to see its attributes, find every feature sharing a value, and jump between the map and the JSON.

Visual
Floating inspector card on the map; Points / Lines / Polygons filter chips with counts.
Interaction
Map selection selects the JSON text; the editor cursor highlights on the map.
straightenmeasure
Measure and capture

A consultant needs an exact coordinate, the length of a route, and the bounding box of an area to paste into a query.

Visual
Pick point / Measure / Bounding box toggles, a result block and a hint bar on the map.
Interaction
Click to add points, double-click to finish; copy the result or add it to the data.
format_paintstyle
Label and colour

Before a client call, the consultant labels each district with its name and colours districts by population.

Visual
Label and choropleth selects, and a nine-step sequential legend with min and max.
Interaction
Render-only styling; simplestyle colours are honoured unless a choropleth is on.
mapmap
Navigate the map

Anyone pans, zooms, tilts and switches basemaps, and expects the app to remember where they were next time.

Visual
Vertical boxed toolbar, basemap menu, tile grid toggle, cursor readout.
Interaction
Fit, reset north, map-only with Esc, resizable split, view saved locally.
Questions the agent would have asked hereanswered as decisions instead
helpWhat colour are features on the map?
Brand accentChart palette

DESIGN.md allows raw colours only for chart data, and map features are data. So: qualitative colour 1 (blue) for features, colour 7 (pink) for the selection, colour 3 (cyan) for matches, and the sequential scale for the choropleth.

helpHow should problems show up?
Inline alert + gutterToasts for results

Validation failures persist until fixed, so they get an alert and gutter markers. Short-lived results (loaded, copied, highlighted) get toasts, which go away on their own.

Fix 1
Remove baseUrl

The script takes the latest Vite template, which now ships TypeScript 7, where baseUrl no longer exists. Path aliases still work without it.

Fix 2
Delete a demo file

The dropdown-menu item also installs a demo file from the design system's website, which imports pages that only exist there.

Fix 3
Sharp icons only

The CSS imported all three Material Symbols families, about 13 MB of fonts. DESIGN.md allows only Sharp, so only Sharp is loaded.

balance
A judgement callThe skill says "do not hand-roll" the scaffold. So the agent kept the script's output, made the three smallest fixes that would get it building, and recorded each one in build.deviations. It did not start over by hand.

Stage 5 · verify (added by the agent)

Prove it in a real browser

The skill ends at Build. But the brief said "test all of it", and a map app can look fine in code and be broken on screen. So the agent added a verify stage: type-check, lint, unit tests, browser tests that click real pixels on the map, and a look at every screenshot.

  • geo-math.test.ts: distances, bounding boxes, tiles, quadkeys, TMS rows
  • locate.test.ts: feature to editor-text ranges, append and merge
  • app-logic.test.ts: properties, matches, deep links, persistence

Bugs that only a browser could findevery one fixed, most with a test so it can't return
The map ignored every clickbrowser test
Symptom
No click on the map registered at all.
Cause
MapLibre's own stylesheet sets position: relative on the map. That CSS isn't in a cascade layer, so it beat Tailwind v4's layered absolute inset-0 and collapsed the map's hit area.
Fix
Put the Tailwind positioning on a wrapper div and leave the library's element alone.
Every line was 0 px widescreenshot
Symptom
Lines were invisible and polygons had no fill.
Cause
In MapLibre expressions, to-number(null) is 0, not the fallback. Features without a stroke-width property got width 0.
Fix
Guard every style property with has, plus a test that evaluates the real expressions.
Clicking London selected Dublinbrowser test
Symptom
At world zoom, the wrong capital opened.
Cause
Point hit boxes overlap, and the first match won.
Fix
Pick the point nearest to the cursor on screen.
The "swapped coordinates" sample passedunit test
Symptom
A deliberately broken sample showed no error.
Cause
Edinburgh with lng and lat swapped is still a valid place, in the Indian Ocean near the Seychelles.
Fix
Use San Francisco instead: swapped, its latitude would be −122, which is impossible.
A pressed toolbar button went blankscreenshot
Symptom
The tile grid button showed an empty square when on.
Cause
The icon colour equalled the pressed fill colour when the button was used on its own.
Fix
Switch the icon to the inverse colour in the pressed state. Logged as finding F10.
Selected text was unreadablescreenshot
Symptom
Selecting JSON in dark mode hid the text.
Cause
The planned selection token was 88% opaque.
Fix
Use --fill-tertiary, recorded as a deviation.

Smaller fixes from the screenshot review: map labels were italic (the basemap's font list starts with an italic face), polygon labels were offset like point labels, the tool hint covered the search box, the editor status was clipped, and the map attribution lost its styling to MapLibre's CSS.
